## ស្ថាបត្យកម្មផ្ទាំងបញ្ជាកណ្តាលសម្រាប់ប្រព័ន្ធរោទិ៍ការពារអាជីវកម្ម

[ប្រព័ន្ធផ្ទាំងបញ្ជាកណ្តាល] គឺជាបេះដូងស្នូលនៃហេដ្ឋារចនាសម្ព័ន្ធសុវត្ថិភាពពាណិជ្ជកម្ម។ វាមិនត្រឹមតែទទួលសញ្ញាបញ្ចូលពីសេនស័រប៉ុណ្ណោះទេ ប៉ុន្តែថែមទាំងគ្រប់គ្រងតក្កវិជ្ជានៃតំបន់ (zone logic) ការបែងចែកតំបន់បញ្ជា (partitions) ការដំណើរការសញ្ញាព្រឹត្តិការណ៍ និងការកំណត់ផ្លូវបញ្ជូនសញ្ញាទៅកាន់ស្រទាប់ទំនាក់ទំនង។ ក្នុងប្រព័ន្ធអាជីវកម្មខ្នាតធំ [ប្រព័ន្ធផ្ទាំងបញ្ជាកណ្តាល] ត្រូវតែធានាបាននូវដំណើរការដែលអាចទុកចិត្តបាន ការរក្សាកំណត់ត្រាព្រឹត្តិការណ៍ (event buffer) និងការឆ្លើយតបទៅនឹងការជ្រៀតជ្រែកក្នុងប្រព័ន្ធ។

នៅក្នុងប្រព័ន្ធរាយការណ៍សញ្ញារោទិ៍ទំនើប [ពិធីការរាយការណ៍ព្រឹត្តិការណ៍ IP SIA DC-09] បានក្លាយជាស្តង់ដារមាសសម្រាប់ការបញ្ជូនទិន្នន័យព្រឹត្តិការណ៍សុវត្ថិភាពតាមបណ្តាញ IP និងបណ្តាញកោសិកា (Cellular)។ មិនដូចពិធីការ Contact ID បែបបុរាណដែលបង្កើតឡើងសម្រាប់បណ្តាញទូរស័ព្ទដី (PSTN) នោះទេ SIA DC-09 ត្រូវបានរចនាឡើងជាពិសេសសម្រាប់រចនាសម្ព័ន្ធកញ្ចប់ទិន្នន័យ IP ដែលគាំទ្រការអ៊ីនគ្រីប (Encryption) ការផ្ញើទិន្នន័យលម្អិត និងការកំណត់អត្តសញ្ញាណគណនីបានយ៉ាងច្បាស់លាស់។

ទោះជាយ៉ាងណាក៏ដោយ នៅក្នុងការដាក់ពង្រាយជាក់ស្តែង ការមិនត្រូវគ្នារវាងទម្រង់រាយការណ៍និងអ្នកទទួល CMS អាចបង្កើតការបកស្រាយព្រឹត្តិការណ៍ខុស។ បញ្ហានេះកើតឡើងនៅពេលដែលការផ្គូផ្គងកូដព្រឹត្តិការណ៍ (event code mapping) ឬទម្រង់រចនាសម្ព័ន្ធគណនី (account structure formatting) រវាងផ្ទាំងបញ្ជានិងកម្មវិធីគ្រប់គ្រង CMS មិនត្រូវគ្នាយ៉ាងល្អិតល្អន់។ ជាលទ្ធផល ព្រឹត្តិការណ៍រោទិ៍ពិតប្រាកដអាចនឹងត្រូវបកស្រាយថាជាសញ្ញាបច្ចេកទេសទូទៅ ឬសញ្ញារោទិ៍តំបន់មួយអាចនឹងត្រូវបង្ហាញខុសតំបន់នៅលើអេក្រង់របស់ប្រតិបត្តិករ។

## ស្ថាបត្យកម្មទំនាក់ទំនងពីរផ្លូវសម្រាប់ភាពធន់នឹងការបាត់បង់បណ្តាញ

![មុខងារប្រព័ន្ធត្រួតពិនិត្យសញ្ញារោទិ៍តាមបណ្តាញ Athenalarm](https://files.athenalarm.com/images/Athenalarm-hero-Cloud-based-integrated-network-alarm-monitoring-system.jpg)  

[ភាពធន់នៃការកំណត់ផ្លូវទំនាក់ទំនងបណ្តាញពីរផ្លូវ] គឺជាយន្តការការពារដ៏សំខាន់សម្រាប់ធានាថា សញ្ញារោទិ៍អាសន្ននឹងត្រូវបញ្ជូនទៅដល់មជ្ឈមណ្ឌលត្រួតពិនិត្យ ទោះបីជាបណ្តាញទំនាក់ទំនងចម្បងជួបប្រទះការរំខាន ឬការកាត់ផ្តាច់ក៏ដោយ។ ប្រព័ន្ធដែលមានស្ថាបត្យកម្មពីរផ្លូវ (Dual-Path) ជាទូទៅប្រើប្រាស់បណ្តាញ IP/Ethernet ជាផ្លូវចម្បង និងបណ្តាញ 4G/LTE កោសិកាជាផ្លូវបម្រុង (ឬ PSTN ក្នុងបរិស្ថានចាស់)។

កត្តាវិស្វកម្មដ៏សំខាន់នៅក្នុងស្ថាបត្យកម្មនេះគឺយន្តការត្រួតពិនិត្យបេះដូង (Heartbeat Supervision / Polling)។ ការបាត់បង់ផ្លូវទំនាក់ទំនងចម្បងដោយគ្មានការត្រួតពិនិត្យបេះដូងអាចបង្កឱ្យមានការខកខានក្នុងការបញ្ជូនព្រឹត្តិការណ៍ ដោយសារតែផ្ទាំងបញ្ជាមិនអាចដឹងថាក្រែឌីតបណ្តាញចម្បងបានធ្លាក់ចុះ ហើយមិនបានធ្វើការប្តូរផ្លូវ (Failover) ទៅកាន់បណ្តាញបម្រុងបានទាន់ពេលវេលានោះទេ។ ការកំណត់ចន្លោះពេល Heartbeat ត្រូវតែធ្វើឡើងដោយប្រុងប្រយ័ត្ន៖ ប្រសិនបើកំណត់ចន្លោះពេលខ្លីពេក វាអាចបង្កជាសញ្ញាអាសន្នភូតភរដោយសារបណ្តាញប្រែប្រួលបណ្តោះអាសន្ន ប៉ុន្តែប្រសិនបើវែងពេក វាអាចធ្វើឱ្យការកាត់ផ្តាច់បណ្តាញមិនត្រូវបានរកឃើញក្នុងរយៈពេលរាប់ម៉ោង។

## ស្ថាបត្យកម្មមជ្ឈមណ្ឌលត្រួតពិនិត្យសញ្ញារោទិ៍ CMS

[ស្ថាបត្យកម្មអ្នកទទួលមជ្ឈមណ្ឌលត្រួតពិនិត្យកណ្តាល] (Central Monitoring Station / CMS) គឺជាចំណុចចុងក្រោយនៃខ្សែសញ្ញារោទិ៍ ដែលទទួល បកស្រាយ និងបង្ហាញព័ត៌មានព្រឹត្តិការណ៍ទៅកាន់ប្រតិបត្តិករដើម្បីធ្វើការឆ្លើយតប និងដំឡើងកម្រិតការចាត់វិធានការ។ ដំណើរការទាំងមូលចាប់ពីសេនស័ររហូតដល់ប្រតិបត្តិករត្រូវតែបង្កើតបានជាខ្សែសញ្ញាជាប់លាប់ និងគ្មានចំណុចបរាជ័យទោល (Single Point of Failure)។

![ដ្យាក្រាមប្រព័ន្ធត្រួតពិនិត្យសញ្ញារោទិ៍តាមបណ្តាញ](https://files.athenalarm.com/images/Athenalarm-network-alarm-monitoring-system-1-1024.jpg)  

ដំណាក់កាលនៃខ្សែសញ្ញារោទិ៍ពាណិជ្ជកម្ម៖

1. **ស្រទាប់សេនស័រ (Sensor Layer)**៖ ឧបករណ៍ PIR, Contact ទ្វារ, សេនស័ររំញ័រ, ប៊ូតុងអាសន្ន ដែលធ្វើការរកឃើញព្រឹត្តិការណ៍ដំបូង និងបង្កើតសញ្ញាបញ្ចូល។
2. **ស្រទាប់គ្រប់គ្រង ([ប្រព័ន្ធផ្ទាំងបញ្ជាកណ្តាល])**៖ ដំណើរការតក្កវិជ្ជាតំបន់ រៀបចំភាគថាស (Partitions) និងបង្កើតកូដព្រឹត្តិការណ៍នៅក្នុងកំណត់ត្រា។
3. **ស្រទាប់ឧបករណ៍ទំនាក់ទំនង (Communicator Layer)**៖ ធ្វើទ្រង់ទ្រាយទិន្នន័យតាមពិធីការរាយការណ៍ (ដូចជា [ពិធីការរាយការណ៍ព្រឹត្តិការណ៍ IP SIA DC-09])។
4. **ស្រទាប់ផ្លូវបញ្ជូន (Transport Path)**៖ បញ្ជូនទិន្នន័យតាមរយៈ IP, Cellular ឬ PSTN ដោយមាន [ភាពធន់នៃការកំណត់ផ្លូវទំនាក់ទំនងបណ្តាញពីរផ្លូវ]។
5. **ស្រទាប់អ្នកទទួល ([ស្ថាបត្យកម្មអ្នកទទួលមជ្ឈមណ្ឌលត្រួតពិនិត្យកណ្តាល])**៖ ទទួលកញ្ចប់ទិន្នន័យ បកស្រាយលេខកូដ និងបញ្ជូនទៅកាន់ [កម្មវិធីគ្រប់គ្រងត្រួតពិនិត្យ](https://athenalarm.com/burglar-alarm/alarm-software/network-alarm-center-management-software/)។

## បញ្ជីផ្ទៀងផ្ទាត់ការធ្វើអន្តរប្រតិបត្តិការជាមួយ CMS

មុនពេលខ្សែស្រឡាយផ្ទាំងបញ្ជាត្រូវបានដាក់ឱ្យប្រើប្រាស់ក្នុងគម្រោងជាក់ស្តែង ចំណុចខាងក្រោមត្រូវតែពិនិត្យ និងផ្ទៀងផ្ទាត់ជាជំហានៗ៖
